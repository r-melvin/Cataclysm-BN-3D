The upstream-merge problem

This is the real constraint on how much you can trim. The fork is 203 files changed (+29,113 / -487) against upstream: 130 new files (about 16k lines of r3d_*, onboarding, status report, UI theme and 25 test files), and 73 modified upstream files (+1,562 / -487). Nothing is deleted yet.

  • Deleting upstream-owned paths causes modify/delete conflicts every time upstream touches them. That makes android/, translated docs and the CI files good candidates (upstream rarely changes them), and game source a poor one. How often upstream touches each path was not checked.
  • Only 4 modified source files exceed 100 changed lines: options, sdltiles, handle_action and input. The main merge risk is upstream changing sdltiles.cpp or cata_tiles.h.
  • About 12 modified files touch pure game logic (warning cleanups plus one map-bounds fix, e.g. mapbuffer -101 lines). That is avoidable friction.
  • Retiring the 2D path is not a trim. The 3D view is a toggle inside the SDL3 tiles build and reuses cata_tiles and the cursesport menus.

Proposed order

  1. Free the disk. Remove the 3.8 GB stale tmp_pack_q0VdVp (nothing references it; no git process is running). Needs your OK.
  2. Safe deletions that upstream rarely touches (one commit each, each followed by a build): android/; build-data/osx with its CMake block; unused tilesets; translated docs; most of .github, msvc-full-features, doxygen_doc, utilities.
  3. Tooling. Drop deno, the TypeScript and JS, and the docs-site tooling. Update AGENTS.md in the same commit.
  4. Docs moves. Create docs-archive for research, repoint the BACKLOG and AGENTS links, move player guides to the wiki.
  5. Reorganise our code. Move r3d_* source and tests into subdirectories so the fork's files are separated from upstream's.
  6. Data overlay (later, optional). Pin an upstream commit, sparse-fetch data/, and keep only the 16 fork data files as an overlay. Needs checks on --datadir for tests and CMake's direct data/ references.
  7. Curses retirement follows the UI redesign (UI-02), screen by screen.

Verification after each step: cmake --build --preset linux-full --target cataclysm-bn-tiles cata_test-tiles and the [r3d] test filter (the full sharded suite took 6:52 per linux-test-profile.md; not run here).

Decisions I need from you

  1. Keep Windows or macOS support? This decides whether the Visual Studio, macOS bundle and Windows scripts go.
  2. Will upstream merges continue indefinitely? If yes, avoid deleting game-logic paths. If you plan to stop merging, you can trim much harder.
  3. Delete the 3.8 GB stale pack file now?
  4. Archive android/ on a branch, or delete it (it stays in history either way)?
  5. Drop deno entirely, or keep a minimal docs:gen for the Lua reference?
  6. Keep the clang-tidy plugin and JSON formatter in the linux-full preset?
  7. Keep the PO and translation tooling, or take translations from upstream only?
  8. Go ahead with the data overlay approach, or stay with in-tree data for now?
