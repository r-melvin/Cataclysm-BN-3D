01. Pain points, ranked

Sourced complaints about Cataclysm (DDA and BN) menus and about the UIs of comparable games, ranked by how many distinct sources the research actually read. Verbatim quotes with links; the full lists are in research/a_cdda_bn_pain_points.md and the per-game files.

How much to trust this

  • Reddit, YouTube comments and the Steam discussion board were not reachable from the research tools (blocked, age-gated or 403). The brief asked for r/cataclysmbn, r/cataclysmdda, r/roguelikes, r/gamedesign and accessibility subreddits; none were mined. Nothing below comes from Reddit. This is the largest gap in the research.
  • CDDA/BN evidence comes from GitHub issues (read via the API), the CDDA Discourse forum (read via its JSON endpoint) and the 151 most recent Steam reviews of CDDA (via the reviews API). Counts are "distinct items read", not a population survey; a count of 16 means sixteen things, not sixteen percent.
  • Comparable-game quotes were fetched through a summarising fetch tool; the agents flagged that wording may not be character-exact. Items marked [snippet] were never opened.
  • Many "UI audit" GitHub issues are developer-filed. They are counted separately where it matters.

"Many UIs are clunky to use, and require the player to "get used to" them." @olanti-p, BN #3602, 2023-11-09. https://github.com/cataclysmbn/Cataclysm-BN/issues/3602

2. Keybindings

"Its a great game that is unfortunately ruined by an ancient and awkward control scheme that is in desperate need of an overhaul." Steam review, negative, 2025-01-25. https://steamcommunity.com/profiles/76561198040659710/recommended/2330750/

"the lack of consistent keys (ie press B to back out of menu or 2 or whatever) is very frustrating." Steam review, negative, 2023-12-20. https://steamcommunity.com/profiles/76561198011358609/recommended/2330750/

"This renders the menu unusable, as in teh carat will not move when the newly bound key is pressed." @JBloodthorn, CDDA #45927 (changing movement keys breaks menu navigation), 2020-12-09. https://github.com/CleverRaven/Cataclysm-DDA/issues/45927

"#86193 added batch size increase and batch size decrease bindings, setting their defaults to to + and -, but prioritize and deprioritize already had those as their default keys" @esotericist, CDDA #86331, 2026-04-07. https://github.com/CleverRaven/Cataclysm-DDA/issues/86331

"The complexity of the giant amount of screens each with its own keybinds is another barrier, that is not fun to master." @thedyze, BN #5442, 2024-09-27. https://github.com/cataclysmbn/Cataclysm-BN/issues/5442

Codebase fact (verified): data/raw/keybindings/keybindings.json holds 585 actions in 61 contexts with 674 keyboard, 28 gamepad and 16 mouse bindings; the default-mode context alone has 132 actions. Per-screen contexts with their own keys are the structural cause.

3. Upstream ImGui migration defects (CDDA only; BN has no ImGui)

"Brain immediately complains that the fonts look.. blurry? They definitely look off and not as crisp as the menu just before." @NetSysFire, CDDA #73120, 2024-04-19. https://github.com/CleverRaven/Cataclysm-DDA/issues/73120

"imGUI still has several major problems in the curses build that makes menus difficult to use." @SandwichPie, CDDA #82161, 2025-07-31. https://github.com/CleverRaven/Cataclysm-DDA/issues/82161

"Currently, the input_context turns all mouse clicks into the SELECT action, no matter where the user actually clicked." @db48x, CDDA #75288, 2024-07-28. https://github.com/CleverRaven/Cataclysm-DDA/issues/75288

"On Windows with display scaling set to 200%, mouse clicks on the ImGui-rendered main menu land on the wrong entry." @YellowBee123, CDDA #88651, 2026-09-13. https://github.com/CleverRaven/Cataclysm-DDA/issues/88651

"Uh... I just started playing experimental version of cdda and I don't like new "graphical" ui of some windows." ... "Like, escape menu is now not ascii-like and I can't find setting to disable it." @AnimeAss, Discourse 29530, 2024-11-22; reply @Profugo_Barbatus: "Nope, the imgui migration is not optional." https://discourse.cataclysmdda.org/t/changing-the-menu-interface/29530

The "looks like a dev tool" phrase from the brief was not found verbatim anywhere. Praise was thin: one reviewer comment, "Overall the UI works really well" (@db48x on PR #73134, 2024-05-03). Lesson: a migration that ships half-done, with a second text renderer and two mouse models, generates a long tail of bugs and a "can I turn it off" reaction. Whatever BN builds must own one text path and one mouse model, and must not expose a half-migrated state for years.

Codebase fact (verified): every screen is laid out in fixed character cells on an 80x24-minimum grid; font size changes require a restart (FONT_SIZE, MAP_FONT_SIZE, OVERMAP_FONT_SIZE in src/options.cpp:2313-2320). There is no wrapping layout engine.

6. Mouse

"There is no full mouse support. Partial mouse support is present, but for many cases it's impossible to interact with the UI using mouse." @olanti-p, BN #3602. https://github.com/cataclysmbn/Cataclysm-BN/issues/3602

Codebase fact (verified): src/ui.cpp (uilist), inventory_ui.cpp, crafting_gui.cpp, advanced_inv.cpp, newcharacter.cpp and main_menu.cpp contain zero mouse or coordinate handling; a left click in a uilist activates the highlighted row without hit-testing the pointer. Only look-around, targeting and query_popup register COORDINATE.

Sidebar (prior art from the CDDA fork research, GitHub issue #27367 and PR #71109)

"Nearly everything on the current sidebar is important in nearly all situations" unnamed commenter, CDDA #27367. https://github.com/CleverRaven/Cataclysm-DDA/issues/27367

"Sidebar take too much space ... The overall feeling is messy" nsklaus, CDDA #27367.

"if it's so dense you can't understand it, it's too dense" kevingranade, CDDA #27367.

"Please allow this to be an option" CoroNaut, CDDA #27367 (on hiding information by context).

These four quotes bracket the sidebar problem: players want all the state, find the sidebar messy, and distrust anything that hides state without a switch. The user's instruction for this fork (remove the sidebar in 3D mode) is consistent with the first three if, and only if, every removed item is reachable as text on demand (F4 report, character sheet) and the "show always" switch exists for the vitals strip.

Positive signals (what not to break)

  • CDDA advanced inventory called "actually incredibly intuitive to use" by one 2025 Steam reviewer (not attributed to any UI framework). The two-pane move model has fans; the new inventory keeps a two-pane move mode.
  • The ZenFS thick sidebar was praised ("I've been using it all day on my ultra wide monitor and it's lovely", PR #71109). Some players want more on screen, not less. The classic build keeps its sidebar untouched; 3D mode offers the "always show vitals" switch and the character screen.
  • Dwarf Fortress Steam kept its density and fixed navigation (scrollbars, tabs) and was called "a large step up" (PCGamesN 2020, V). Density is not the enemy; unnavigable density is.
