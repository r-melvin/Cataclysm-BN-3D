05. Implementation plan

Phased, ordered milestones. Effort is for one experienced developer working on this alone (S ≤ 1 week, M 2-3 weeks, L 4-6 weeks, XL > 6 weeks); parallel streams are noted where a second person helps. "Files" are the likely touch points; new code lives under src/ui/. Every milestone ends with the full build of cataclysm-bn-tiles and cata_test-tiles, the [r3d] test run with CATA_TEST_COMPUTE_ACCELERATION=cpu, and the screenshot suite.

Sequencing constraints set by the user: the 3D sidebar removal (M3) happens only after the HUD design in 03_design.md §4.1 and §3.1 is approved, and with no stopgap HUD in between. Decisions of 2026-10-21 folded in: curses is retired (BACKLOG.md UI-02; milestone M1.5 and phase 3 inside M11; costs in 06_frontend_options.md §4), the frontend stays SDL3 unless the decision gate at the end of M1 fails (06_frontend_options.md §3), and the Tutorial and Guided Play merge into one guided start (UI-01; milestone M9.5).

Smallest valuable slice

M1 + M2: the widget layer with the Settings screen and the Controls editor, and real gamepad support. It ships remapping of every device (fixing a verified defect: gamepad buttons do not work today), the command palette, UI scale and the narrator skeleton, without touching a single gameplay screen. It is the foundation every later screen needs, and it is testable on its own.

Parallelisation summary

  • After M1 (gate passed): M1.5, M2 and M4 in parallel; M3 after M2 and HUD approval.
  • After M3: M5 (two streams), M6 (three streams) and M8 in parallel.
  • M7 after M5; M9 anytime after M4; M9.5 after M6 and M9; M10 last of the screens; M11 after all.
  • Critical path: M0 → M1 → M2 → M3 → M5 → M7 → M10 → M11 ≈ 26-34 weeks for one developer (the cells backend's 15-20 % per-screen cost is gone; M1.5 and phase 3 add 3 weeks off the critical path); about 17-21 weeks with two.

Risks (whole programme)

  1. Two UIs for a long time. Mitigation: milestone order puts the most-used screens first; every new screen fully replaces its legacy screen in the same milestone (no half states, the CDDA lesson).
  2. Upstream merge friction from the curses retirement. Every #else branch deleted in a file upstream still changes will conflict. Mitigation: delete guards only in files this fork already diverges in; keep the rest until the project decides whether upstream merges continue (open question 1).
  3. Hidden sidebar consumers. Mitigation: M3 greps and tests; classic snapshots catch regressions.
  4. Mods and Lua depend on context ids and lua_sidebar_widgets. Mitigation: aliases, and the badge API lands in M3.
  5. Platforms unverified (macOS, Windows, Deck). Mitigation: per-OS testers before M8 is called done; speech backends fail to no-op.
  6. Scope creep in the widget layer. Mitigation: the 12-widget list is the list; new widget types need a design note.

Open questions only the user can decide

  1. Upstream merges: does this fork still merge from upstream Bright Nights? It decides how aggressively #if defined(TILES) guards are removed (06_frontend_options.md §4).
  2. Approve the HUD design (§4.1 and §3.1 of 03_design.md) before M3 starts, including the clock-on-compass gating by a watch and the single minimap.
  3. Hotbar slot 1 = wielded item, fixed? Or all eight free, with the wielded item shown elsewhere in the vitals strip.
  4. Default keyboard keys: keep the "Legacy" binding group on by default for veterans (longer Reference list) or off (clean 32-key default, veterans opt in)?
  5. Feature cuts: Defense mode and minigames stay on the legacy path, or are cut at M11?
  6. Lua sidebar widgets become HUD badges plus F4 text (proposed), or a dedicated on-demand "Mod" panel?
  7. AccessKit phase (M12): fund it (adds a Rust toolchain or prebuilt binaries to CI) or stop at self-voicing?
  8. Speech on Windows: NVDA client + SAPI (proposed) versus Tolk (covers JAWS too but is unmaintained, LGPL-3.0)?
  9. Advanced file location and naming: config/advanced.json next to options.json, or a single options.json with the curated/advanced split only in the UI?
