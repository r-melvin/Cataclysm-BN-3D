K. Onboarding, tutorial and discoverability in complex-systems games

Research pass for the UI redesign. Scope: how comparable games teach players their systems and surface controls, plus classic roguelike help and action-menu approaches.

Verification key

  • FETCHED: page was fetched and the quote was confirmed in the fetched text. The quote is verbatim.
  • SNIPPET: quote appears only in a search-result summary. Not confirmed against the page. Treat as paraphrase unless re-checked.
  • UNVERIFIED: memory or a claim with no source found in this pass. Do not cite as fact.

Extracted rules (with sources)

  1. Help text must be visible at the moment it matters. Dwarf Fortress's onboarding was an explicit goal of the Steam release, with "a new helpful tutorial to onboard unfamiliar players" (Kitfox devlog). Players reported that tutorial pop-ups vanish too fast (BG3, snippet). Hints need enough dwell time and must be re-readable.
  2. Teach by doing, then show the system once. Subnautica players quit when a required action (mining stones) was never surfaced; Valheim's Hugin gives tips only at milestones and then goes quiet, leaving much unexplained. Tips should appear when the player encounters the mechanic, not only at a fixed early point.
  3. Keep a lookup reference after the hint. RimWorld's Learning helper can be "expanded and searched for any lesson" (wiki); Valheim keeps Hugin's tips in the Compendium behind Tab; DCSS uses '?' as the always-available help key. Hints without a re-open path were the Valheim and BG3 complaint.
  4. Show controls contextually, not in a manual. RimWorld lessons are "shown as needed by circumstance"; Caves of Qud's tutorial is praised as "a nice introduction" but only "scratches the surface" (GamingOnLinux). A short tutorial covering a small subset is accepted by players; a tutorial that omits whole systems is criticised (Project Zomboid, BG3).
  5. Mark lessons learned automatically. RimWorld marks a lesson learned when the action is performed, and allows manual marking. This avoids repeat nagging.
  6. Make tooltips the main explanation layer, but know their limits. Stellaris praise for tooltips is paired with complaints that nested terms need prior knowledge (snippet only).
  7. Skippable tutorial with a re-entry point. Deep Rock Galactic's training mission is skippable and revisitable from the Miner's Manual (wiki snippet). Dwarf Fortress's tutorial is offered at start but reviewers still advise doing it.
  8. Give the player the discovery path, but not the blocker. Noita's no-hand-holding design is praised by critics and disliked by newcomers (snippet). For a complex game, avoid making a required system invisible.

Patterns worth adopting (for a Cataclysm-BN-3D UI redesign)

  • A searchable in-game lesson or help index, reachable from the same key as the main menu (DCSS '?', RimWorld Learning helper). Lessons should be re-openable.
  • Just-in-time hints tied to real events, auto-marked learned, with a manual dismiss. Avoid timed-only popups; keep them until dismissed or until the action is done.
  • A skippable first-run tutorial that covers the core loop and points to the help index, not a full system dump (DF, Deep Rock).
  • Keep controls visible on screen where they are used (a bottom key hint line) rather than only in a manual, but do not add clutter. Note that this is a design inference; no source in this pass verified a specific key-bar implementation for Brogue or Qud.
  • Surface any feature the player must use early (Subnautica scanner) rather than gating it behind exploration.
